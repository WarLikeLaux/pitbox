Слой координации для параллельных кодинг-агентов: переиспользуемые worktree-воркеры, явная передача работы и детерминированная сборка. Bash CLI плюс MCP-фасад, чьи описания инструментов несут правила воркфлоу, поэтому агенты следуют процессу без правок AGENTS.md.

## Зачем

Кодинг-агенты мешают друг другу в одном чекауте. Создавать worktree под каждую задачу просто, но остаются две проблемы: брошенные worktree копятся как мусор на диске, и у агента нет стандартного способа сказать «задача готова, забирайте».

pitbox отвечает тремя решениями. Worktree здесь лишь рантайм. pitbox владеет жизненным циклом задачи вокруг них: claim, работа, ready, collect, release.

- Фиксированный пул из двух-трёх слотов, созданный один раз рядом с чекаутом и переиспользуемый вечно. Никаких спавнов под задачу, никаких остатков, установка зависимостей оплачивается один раз на слот.
- Маркер готовности. Агент слота заканчивает работу записью `TASK_READY.md`, интегратор собирает только помеченные слоты, а слово пользователя всегда перекрывает маркер.
- Жёсткое разделение ролей. Агенты слотов никогда не мёржат и не деплоят. Интегратор собирает, гоняет полные проверки, деплоит, пушит и возвращает слоты в пул.

## Как это работает

```
your-repo/            your-repo-wt1/       your-repo-wt2/       your-repo-wt3/
main checkout         слот wt1             слот wt2             слот wt3
только интегратор     агент + task-ветка   агент + task-ветка   запасной
```

- Одна задача: работайте прямо в основном чекауте, слоты не нужны.
- Две-три параллельных задачи: по слоту на задачу, основной чекаут принадлежит интегратору.
- Агент слота берёт слот через `pitbox claim` (она атомарно бронирует свободный слот и создаёт task-ветку), проверяет работу внутри слота, соблюдает правила репозитория для коммита и пуша и помечает закоммиченную ветку готовой.
- Интегратор собирает готовые слоты, гоняет полные проверки репозитория, деплоит, пушит и возвращает слоты в пул.

## Быстрый старт

Нужны только bash, git и node для MCP-сервера. Windows работает через WSL.

```bash
curl -fsSL https://raw.githubusercontent.com/WarLikeLaux/pitbox/main/bin/pitbox -o ~/.local/bin/pitbox
chmod +x ~/.local/bin/pitbox
```

Подготовьте репозиторий один раз:

```bash
cd your-repo
pitbox init      # пишет шаблоны .pitbox/, автоопределяет bun или php + docker
pitbox setup     # создаёт ../your-repo-wt1 .. wt3 и ставит зависимости в каждый
```

Опционально научите git глобально игнорировать маркер готовности, чтобы агенты не видели его в `git status` (свои проверки pitbox и так его исключают):

```bash
git config --global core.excludesFile ~/.config/git/ignore
mkdir -p ~/.config/git && echo TASK_READY.md >> ~/.config/git/ignore
```

Повседневные команды:

| Команда | Что делает |
|---------|------------|
| `pitbox init [--stack S] [--force]` | Пишет шаблоны `.pitbox/` для репозитория (стеки: `bun`, `php-docker`, автоопределение) |
| `pitbox setup [N]` | Создаёт пул слотов, по умолчанию три |
| `pitbox claim [slot] [name]` | Атомарно бронирует свободный слот и создаёт в нём task-ветку (сам выбирает слот, если не указан) |
| `pitbox status` | Ветка, грязные файлы, коммиты впереди main, готовность по слотам |
| `pitbox ready <slot> [note]` | Помечает задачу слота готовой, фиксирует HEAD ветки, отказывает на грязном слоте или заглушке ветки |
| `pitbox collect <slot\|ready>` | Мёржит task-ветку слота в основную ветку через `--no-ff`, отказывает при грязном основном чекауте, ветке не main и слотах, изменившихся после маркера |
| `pitbox release <slot>` | Сбрасывает слот на main, удаляет влитую ветку, гоняет release-хуки |
| `pitbox guide` | Печатает полные правила воркфлоу для агентов |

## MCP-сервер

MCP-сервер это zero-dependency stdio-фасад над CLI. Он существует, чтобы агенты видели правила воркфлоу без правок AGENTS.md: каждое описание инструмента несёт нужное правило, а инструмент `guide` возвращает весь воркфлоу целиком.

Подключите любой MCP-клиент:

```json
{
  "mcpServers": {
    "pitbox": {
      "command": "node",
      "args": ["/path/to/pitbox/mcp/server.mjs"]
    }
  }
}
```

Claude Code:

```bash
claude mcp add pitbox -- node /path/to/pitbox/mcp/server.mjs
```

Codex (`~/.codex/config.toml`):

```toml
[mcp_servers.pitbox]
command = "node"
args = ["/path/to/pitbox/mcp/server.mjs"]
```

Хост плагина может запускать MCP-сервер из своего кэша. Поэтому каждый инструмент, работающий с репозиторием, требует параметр `repo`: абсолютный путь к нужному репозиторию или worktree. При подключении сервер передаёт агенту шаги онбординга и правила работы. В новом репозитории вызовите `init` с `repo`, проверьте и закоммитьте `.pitbox/`, затем вызовите `setup` с тем же `repo`.

### Справочник инструментов

| Инструмент | Назначение |
|------------|------------|
| `guide` | Полные правила воркфлоу, вызовите один раз перед остальными |
| `status` | Состояние пула слотов, вызывайте перед сборкой, для новой задачи используйте `claim`, не бронируйте слот руками |
| `claim` | Атомарно забронировать свободный слот и создать в нём свою task-ветку |
| `setup` | Создать фиксированный пул слотов, никаких спонтанных worktree |
| `ready` | Помечать слот готовым, фиксирует HEAD ветки, отказывает на грязном слоте или заглушке, самому не мёржить |
| `collect` | Интегратор: влить ветку слота, или `ready` для всех помеченных, отказывает при грязном основном чекауте и ветке не main |
| `release` | Интегратор: вернуть собранный слот в пул |
| `init` | Написать шаблоны `.pitbox/` для репозитория, закоммитить результат |

## Плагины для Claude Code и Codex

Плагин бандлит MCP-сервер и скилл `integrate`, так что правила воркфлоу и процедура интегратора приезжают вместе.

Claude Code:

```
/plugin marketplace add WarLikeLaux/pitbox
/plugin install pitbox@pitbox
```

Codex (0.157+):

```
codex plugin marketplace add WarLikeLaux/pitbox
codex plugin add pitbox@pitbox
```

`mcp.json` плагина использует спек-переменную `${PLUGIN_ROOT}`, поэтому плагин сам подключает свой MCP-сервер в обоих агентах. На старых сборках Codex без поддержки плагинов зарегистрируйте сервер вручную, как показано выше, и скопируйте `plugin/skills/integrate` в свою директорию скиллов.

### Обновление локальных установок

Если изменился `plugin/`, повысьте версию одновременно в `plugin/plugin.json`, `plugin/.claude-plugin/plugin.json` и `.claude-plugin/marketplace.json`. При прежней версии Claude оставит старую копию в кэше. Прогоните `bash scripts/smoke.sh`, закоммитьте изменения и запушьте `main`. После этого обновите установку на этой машине:

```bash
bash scripts/update-installed.sh
```

Скрипт требует чистый чекаут на опубликованном коммите `origin/main`. Он обновляет маркетплейсы Codex и Claude, оба установленных плагина и `~/.local/bin/pitbox`, затем сравнивает кэши плагина с исходниками. Если CLI установлен в другом месте, задайте `PITBOX_CLI_TARGET`. Новые версии плагинов загрузятся в новых сессиях Codex и Claude.

## Конфигурация репозитория

pitbox глобальный, специфика репозитория живёт в `.pitbox/` рядом с кодом.

- `.pitbox/config`: переменные шелла, `MAIN_BRANCH=<branch>` перекрывает автоопределение. Порядок автоопределения: `MAIN_BRANCH` из конфига, затем `origin/HEAD`, затем текущая ветка. `REQUIRE_PUSH=1` заставляет `pitbox ready` требовать запушенную ветку, по умолчанию выключено.
- `.pitbox/setup.sh`: вызывается с директорией слота как `$1` после добавления worktree и на release. Шаблон `bun` гоняет `bun install --frozen-lockfile`, шаблон `php-docker` гоняет `composer install`.
- `.pitbox/release.sh`: опциональная доп. уборка на release, иначе используется `setup.sh`.

В репозиториях, настроенных старой версией pitbox, переименуйте `.slots/` в `.pitbox/` перед запуском нового CLI. Старый каталог больше не читается.

`pitbox init` пишет эти шаблоны и определяет стек по `composer.json` и `bun.lock` или `package.json`. Шаблоны стеков естественное место для контрибьюторов новых стеков.

Для php + docker проектов параллельным слотам нужна изоляция compose на слот: свой `COMPOSE_PROJECT_NAME` на слот, уникальные хост-порты и никаких фиксированных `container_name` в compose-файлах. Шаблон печатает об этом напоминание.

## Заметки

- Слоты живут соседними директориями: `../your-repo-wt1` и так далее, рядом с чекаутом.
- Мёржи специально `--no-ff`, пачки задач остаются видимыми в истории.
- Здесь нет конфликта с нативными worktree-механиками конкретных агентов. Сессии Claude Code могут использовать встроенную worktree-изоляцию, pitbox это общий пул и процедура сборки для всех остальных.
- npm-пакета пока нет, ставьте из клона. Поставьте звезду, если нужен.
